###############################################################################
# 0) NOUVEAUTES 2026-11 — Crypto, fichiers et reconnaissance (tapez `help crypto` / `help recon`)
###############################################################################

Shell Nebula — confort du terminal
  - Tab complete les commandes et les chemins ; une commande deja tapee est proposee en gris (fleche droite).
  - commande > fichier (ou >>) enregistre la sortie dans l'espace de travail ; --json pour les outils recents.
  - alias, run <script>, tuto (visite guidee), update. rm supprime dans l'espace de travail ; exec lance une commande systeme.

Tools.virtualfs — Espace de travail (ls, cd, mkdir, cat, grep, rm, mv, cp, tree, find, import, export)
  - Description : systeme de fichiers de Nebula, sauvegarde avec le profil. Chemins comme sous Linux (~, .., /).

Tools.tracewave — Analyse de captures reseau (commande : tracewave, alias tw)
  - Description : lit un fichier .pcap ou .pcapng ; machines, conversations, services, domaines, sites HTTPS, et constats automatiques (protocoles en clair, identifiants visibles avec valeur masquee, conflits ARP).
  - Note : tracewave compare <avant> <apres> montre ce qui a change. Capture sous Windows : voir tracewave.help (pktmon).

Tools.reqforge — Atelier de requetes HTTP (commande : reqforge, alias rf)
  - Description : envoyer, rejouer avec modifications, comparer deux reponses, exporter en curl ou Python. Chaque reponse est analysee automatiquement.
  - Note : respecte le perimetre de mission. Une requete = une action (pas d'envoi en masse).

Nebula_IA — Copilote de pentest (commande : ia, alias nebula_ia)
  - Description : lance lui-meme les commandes Nebula, lit les resultats (--json), enchaine et releve les constats avec preuve et correction.
  - Fournisseurs : anthropic (Claude), openai (ChatGPT), gemini, mistral, groq, deepseek, openrouter, ollama (local). Cle : ia key <fournisseur>. Verifier : ia test.
  - Playbooks : ia audit web|tls|reseau|complet <cible> (mission ouverte, cible dans le perimetre).
  - Note : commande reseau = votre accord (sauf ia auto on, dans une mission). Hors perimetre = refuse par le terminal. Ses actions vont au registre. Ctrl+C ou bouton Stop pour l'arreter.

terminal.mission — Mode mission (commande : mission)
  - Description : perimetre autorise, registre de preuves chaine par hash, comparaison entre deux passages, constats, retest, rapport Markdown + HTML (imprimable en PDF) avec tableau de conformite (nLPD, ISO 27001, NIS2).
  - Note : mission ouverte = les commandes reseau hors perimetre sont refusees et tout est enregistre. mission retest rejoue la preuve de chaque constat.

Tools.cryptokit — Encodage, empreintes, mots de passe, fichiers (stdlib uniquement)
  - Commandes : encode, decode, hash, hashid, ipcalc, jwt, pwgen, pwstrength, ts, uuid, strings, fileinfo
  - Plateforme : Cross-platform. Aucune dependance.
  - Note : pwstrength demande le mot de passe apres coup, il n'entre jamais dans l'historique.

Tools.recon — Reconnaissance reseau
  - Commandes : dns, whois, headers, banner, sslscan, subdomain, hostscan
  - Plateforme : Cross-platform (dns utilise nslookup, hostscan utilise ping).
  - Note : a utiliser uniquement sur des cibles autorisees. hostscan est limite a 4096 adresses.

Tools.portscan / Tools.dirb — desormais en parallele
  - scan -a (65535 ports) : environ 1 minute. dirb : 20 requetes simultanees, detection des faux 200.
  - Ctrl+C arrete le scan.

###############################################################################
# 1) OUTILS / MODULES INTERNES (package Tools / ToolsFunction / NebulaGui)
###############################################################################

Tools.shadowviper — Collecte d'informations (commande : shadowviper <cible>)
  - Description : IP, domaine, URL, ASN (AS15169) ou e-mail -> geolocalisation (ip-api, ipinfo), systeme autonome (RIPEstat), WHOIS du domaine, DNS, ports courants, ping et traceroute, avis du modele local.
  - Plateforme : Cross-platform. Le modele local demande scikit-learn (python launch.py --full) ; sans lui, le reste fonctionne.
  - Note : resultats en blocs (dashboard, --json, Nebula IA). Respecte le perimetre de mission.

Tools.dirb — Wrapper local pour brute-forcing de répertoires
  - Description : module interne qui expose une fonction `dirb` utilisée depuis le menu. Peut encapsuler wordlists, scans web.
  - Plateforme : Cross-platform (Python).
  - Note : usage potentiellement bruyant — protéger par SAFE_MODE et confirmer scope avant exécution.

Tools.games.nebulers.Menu_Principale — Mini-jeux intégrés à Nebula
  - Description : module de jeux (nebulers) embarqué pour fun / démonstration UI.
  - Plateforme : Cross-platform.
  - Note : n'affecte pas la pentest, mais utile pour démo / tests UI.

Tools.ping.ping.run_ping_command — Wrapper ping
  - Description : wrapper interne pour exécuter pings (ICMP) et parser résultats.
  - Plateforme : Cross-platform (ICMP nécessite privilèges sur certains OS).
  - Note : sur Linux/Windows, l’usage d’ICMP peut nécessiter privilèges ; prévoir fallback (TCP ping) si pas autorisé.

Tools.nexariescan — XSS reflechis (commande : nexariescan <url> [--delay 0.5] [--pages 50] [--post])
  - Description : parcourt le site (meme domaine) puis teste les parametres d'URL et les formulaires : signale le code injecte renvoye sans echappement.
  - Plateforme : Cross-platform.
  - Note : GET seulement par defaut (--post pour les formulaires POST). Site autorise uniquement ; respecte le perimetre de mission.

NebulaGui.server — Dashboard web Nebula (commande : nebulaGui)
  - Description : tableau de bord dans le navigateur. Activite du terminal en direct, console, recon en un clic, palette de commandes (Ctrl+K).
  - Plateforme : Cross-platform (serveur local Python, aucun framework).
  - Note : accessible uniquement depuis ce PC (127.0.0.1) et protege par un jeton aleatoire.

# 2) BIBLIOTHÈQUES / DÉPENDANCES TIERS UTILISÉES PAR NEBULA
###############################################################################

colorama — Coloration des sorties terminal (Windows friendly)
  - Usage dans Nebula : styliser les messages console.
  - Plateforme : Cross-platform.
  - Note : sur Windows initialise `colorama.init()`; remplace `os.system("color")`.

pyfiglet — Affichage ASCII-art (bannières)
  - Usage : titres / bannière Nebula.
  - Plateforme : Cross-platform.

requests — Requêtes HTTP simples
  - Usage : appels web / APIs.
  - Plateforme : Cross-platform.
  - Note : gérer timeouts, retries, et erreurs réseau.

folium — Génération de cartes HTML
  - Usage : fonctionnalités de mapping / geo (sauvegarde HTML).
  - Plateforme : Cross-platform.
  - Note : ne pas tenter d'ouvrir automatiquement le HTML sur un serveur headless.

keyboard — Lecture d'événements clavier globaux
  - Usage : détection de touches (ex : quitter, shortcuts).
  - Plateforme : Windows (bon support), Linux (nécessite sudo ou capacités), mac (limités).
  - Note de sécurité : nécessite précautions — documenter installation & privilèges (Kali).

psutil — Infos système (process, CPU, mémoire)
  - Usage : monitoring, kill processes, info système.
  - Plateforme : Cross-platform.

tkinter — GUI natif Python (Tk)
  - Usage : fenêtres/dialogs (si GUI activée).
  - Plateforme : Windows, Linux (X), mac.
  - Note : paquet souvent absent sur images minimalistes (installer python3-tk).

pyinstaller — (optionnel) pour créer exécutable Windows
  - Usage : packaging pour distribuer Nebula en .exe.
  - Plateforme : Windows (build), Linux.

json, os, subprocess, socket, platform, getpass, shutil, time, random, math, traceback, unicodedata, ctypes, threading — libs stdlib
  - Usage : utilitaires core du projet (IO, exécution sous-process, manipulation strings, threads).

###############################################################################
# 3) RECOMMANDATIONS / PRÉREQUIS POUR CHAQUE PLATEFORME
###############################################################################

- Windows 10/11 :
  - Installer Python3 (≥3.8), activer "Add to PATH".
  - Préférer lancer Nebula via le venv créé par launch.py (venv/Scripts/python.exe).
  - `keyboard` fonctionne mieux avec droits admin ; testing recommandé dans PowerShell (Admin).
  - Si packaging, construire avec PyInstaller sur une VM Windows.

- Linux / Kali :
  - Installer python3-venv, python3-tk (si GUI), build-essential si besoin.
  - `keyboard` peut nécessiter `sudo` ou `setcap` pour capter certaines touches globales. Documente les besoins.
  - Sur serveurs/headless, utiliser `--headless` pour désactiver tkinter/folium open.
  - Certains outils réseau (raw sockets) nécessitent droits root (sudo).

- Général :
  - Toujours lancer `launch.py` pour créer venv et installer `requirements.txt`.
  - SAFE_MODE activé par défaut : fonctionnalités destructrices sont désactivées jusqu'à activation explicite via variable d'environnement ou option CLI.
  - Documente dans README les modules nécessitant privilèges (keyboard, raw sockets, sniffers).
